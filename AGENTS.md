# dev_fram Agent Instructions

These instructions apply to this framework checkout and its descendants.
The host's applicable instructions also apply. If a host rule conflicts with
this framework contract, identify the conflict before changing shared APIs.

## Read Before Editing

1. Read [coding rules](rules/coding.md) and [documentation rules](rules/documentation.md).
2. Read the [documentation navigation](docs/README.md), then the relevant indexed files.
3. Read [current architecture](docs/specs/current-architecture.md) and
   [host integration](docs/specs/host-integration.md) before changing ownership.
4. Compare the checkout with the recorded baseline and read the actual code.
   Documentation at another version is context, not proof of current behavior.

This repository owns common helpers, bus wrappers, STM32 adapters, ring buffer,
log declarations and demo stubs. It does not own the host's chip-protocol
drivers, facades, application workflow, real board binding or vendor SDK.

`bus/dev` exposes abstract operations. `port_bsp` implements hardware behavior.
The host BSP binds physical resources and startup/IRQ integration. Keep vendor
types and physical resource details within adapters and the host BSP.

## Authority And Evidence

- `rules/` contains applicable existing requirements extracted for this framework.
- The two cross-project guidelines are review drafts, not newly approved rules.
- Current-state documents describe the recorded source baseline.
- Historical plans, excerpts and commit messages are not current instructions.
- A recorded old build or hardware observation does not verify this checkout.
- Keep source hashes, document hashes, commands, outcomes and unverified scope.

No firmware behavior or API is changed by the documentation library itself.
Current code may have documented gaps; do not rewrite unrelated firmware to
make it conform to a draft while doing a documentation task.

## Verification And Handoff

Run from this framework root after documentation changes:

```powershell
python scripts/docs-library.py update
python scripts/docs-library.py check
python tests/docs_library_test.py
git diff --check
```

For firmware changes use the host's supported build and required hardware
observations. A host test is supplementary, not a replacement for that evidence.
Record shared framework changes here; record host-specific board changes in the host.
Do not commit generated firmware, machine configuration or documentation ZIP files.

The host AI entry must explicitly direct agents here. Document discovery differs
between clients; do not assume a nested AGENTS file is loaded for every task.
